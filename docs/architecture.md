# Architecture and execution boundaries

The loopback Node companion serves a fixed asset list and an in-memory repair controller. It binds only to `127.0.0.1` on an ephemeral port. Mutating requests require the exact Host, Origin, JSON content type and an in-memory session token. There is no shell endpoint, package-install endpoint, filesystem editor or general proxy.

`src/controller.cjs` binds read evidence to file hashes, preserves the original task, restricts patch paths and counts operations. Applying a change invalidates its prior public-check result. Finish requires a passing result for the current workspace. The three reference drills accept only their immutable authored baseline, correction and optional regression-trap programs. Their Node `vm` loader is for those fixed authored strings, never for user/model code. Source-bound comparisons identify newly passing and newly failing checks across changed sources; a flat total cannot conceal a regression. These comparison fields never admit execution or unlock Finish.

`src/coding-session.cjs` composes a local-only coder and optional browser planner. The coder returns bounded edit JSON plus a receipt matching the request, workspace and pinned profile. The Ollama adapter rejects remote-routing metadata, requires affirmative cloud-disabled status, pins the selected model digest and effective template/parser metadata, refuses redirects and applies per-request and total-operation deadlines. Metadata checks are not traffic attestation. Timeouts stop client waits; they do not establish stopped backend compute or unloaded models.

Both repair modes supply one current version of every captured task file to the coder, within the context budget. A Nano citation identifies the source supporting its hint; it does not hide other dependencies or widen the writable-file scope. Re-reading a file keeps its history in the controller while the next coder request uses its latest current evidence once.

Configured starts require a one-use, server-issued admission ID supplied before transport. Closing a start revokes that exact offer even if Start arrives late, or cancels its exact admitted session if the success response was lost. Stale offers and cancellation cannot close a replacement. Browser callbacks also bind to their captured session and epoch.

Function intake uses the same authenticated loopback boundary and one-use start admission. It validates source and JSON examples before replacing the current owner. Its controller can edit only `src/function.js`; the generated `contract.json` stays read-only. Manual replacements are explicitly labeled user input and count zero model invocations. `src/function-workflow.cjs` never evaluates source: it requests checks from the trusted qualified verifier, independently validates the exact source/contract binding, and discards canceled or replaced results. The imported task can also enter the existing local-coder flow, with the same read-only contract and verification requirement.

The Firebase adapter uses pinned `firebase@13.3.0` / `@firebase/ai@3.1.0`. The browser bundle is rebuilt with a lockfile, served locally and checked against a manifest of its bytes and build inputs. Source changes make an old bundle unavailable. Guards currently rely on version-specific SDK internals; upgrades need source review and new real-browser validation. Initialization is explicit and gesture-driven. The adapter rejects an unavailable/downloading/downloadable native model before Firebase initialization, although readiness can change during SDK initialization and must be tested in the real browser.

Stop and disposal explicitly destroy the adapter's current owned Prompt API session, including a session created late by an abort-ignoring setup. The pinned SDK's `createSession` boundary is guarded so a released model cannot start a prompt with that late session. Sessions belonging to other models remain outside this ownership scope. Session destruction requests resource release; native process and cache eviction still require runtime observation.

Each Native preparation or decision has a 90-second client wait. A deadline stops that adapter lifetime, releases the caller and reports a bounded timeout diagnostic. Stop and disposal release waits immediately, including when the native provider ignores cancellation. Late rejections are consumed and a late initialization cannot clear a replacement operation's busy state. The deadline does not retry inference, switch to cloud or attest stopped native compute or immediate cache eviction.

The reference advisor requires a failed public check and current read evidence. Its repair-only response contains `needsMoreEvidence`, `evidenceId`, `sourceQuote`, `cause` and `change`. An actionable hint must quote text actually present in its selected current source, with bounded cause/change text. The application constructs the controller action and binds it to the captured request revision; the model supplies no permission or operation fields. Insufficient evidence produces a manual-review outcome. The controller's broader action schema remains the default elsewhere. Stale reads, injected binding fields, invented citations and unmatched quotations are rejected. Quote validation proves literal presence, not causation or repair correctness. Capturing the request before provider waits prevents caller mutation from rebinding a late hint. Bounded failure categories expose no raw provider errors or model output. Navigation and Close discard late advice and request native cancellation. The exported record omits source contents, Firebase configuration, pairing tokens, provider secrets and advisory text. Contract tests use authored outputs; model usefulness requires separate runtime and final-grading evidence.

The optional cloud reviewer has a separate factory and lifetime. Constructing it or previewing a bounded prompt performs no SDK initialization. Send requires the exact immutable, current preview object and a secure-browser user gesture. It uses `ONLY_IN_CLOUD`, explicit nested `inCloudParams`, a pinned model, JSON output constraints, an abort signal and a 60-second wait. The exact previewed prompt is passed to `generateContent`; a separate named Firebase app owns its App Check setup. Responses require the SDK's nested `in_cloud` receipt and known source citations. Revision changes revoke approval. It never invokes the coder, applies edits, grades a fix or silently replaces failed on-device inference. Cancellation is a client lifecycle guarantee, not provider-compute or cost attestation.

The repair prompt presents only the original task, currently read source contents/IDs and public check results. Revision, hashes, operation handles, budgets and permissions remain in the captured application context. The coding session supplies its accepted current public verdicts to this prompt; independent final grading is excluded. This reduces unrelated bookkeeping in the model input without delegating controller authority to the model.

## Qualified execution is a separate requirement

`src/public-verifier-contract.cjs` is closed by default. The explicit verified launcher uses a trusted issuer that snapshots this package's fixed runner sources, builds its pinned image, runs the live Docker qualification suite, verifies source stability, and creates a process-local identity capability. A callback, status boolean, image hash, copied receipt or caller-provided token cannot create that identity. The typed outcome binds exact check IDs, ticket, suite and workspace hash, and keeps infrastructure failures separate from candidate failures. The test-only authored admission composition supplies facts and never executes returned code. Production entrypoints never load that test composition.

The [QuickJS/WASM runner](runner-pilot.md) executes pagination and settings-isolation candidates with closed guest capabilities, interpreter allocation/stack/interrupt limits and an outside watchdog. Settings checks observe successive calls in one guest context; a fresh context isolates each candidate. Only the named implementation file can vary, while its dependency module stays fixed. Its opt-in Docker wrapper adds actual kernel memory/swap/CPU/PID limits and a separately privileged, input-free PID 1 watchdog. Live tests include both drills, native resource faults, stopped children, outside canaries, cancellation and controller SIGKILL. Only a completed runtime qualification enables the image's declared suites. Node `vm` is not the candidate execution boundary. Public checks remain distinct from held-out correctness.

On Windows the trusted issuer launches the fixed Linux sidecar through WSL and communicates over its owned stdin/stdout pipes. The sidecar builds and qualifies its own image; the browser cannot choose a process, shell command, image or Docker API operation. There is no sidecar TCP listener. Closing the registration revokes admission and requests owned-job cleanup. Container PID 1 remains responsible for its own deadline if the outer process disappears.

## Product validation still required

The web build also offers tab-local function repair using a fixed application worker and the shared QuickJS function executor. A pure outcome codec is shared with the Node boundary; importing it cannot resolve or mint Docker admission. Each worker owns a fresh interpreter, receives captured source/contract strings, and exposes no guest-to-browser API bridge. Expected answers remain in the outside grader. A separate worker startup deadline, execution deadline and exact-owner cancellation complement the guest's cooperative interrupt and allocation/stack limits. Browser API termination has no exit receipt and does not impose Docker/kernel bounds. Its explicit `browser-worker-quickjs` capability is never qualified or benchmark-eligible. The Docker issuer still snapshots its curated runner sources and runs its full live qualification independently.

Real Firebase inference has exercised an on-device hint followed by explicit cloud review in hosted Chrome, with normal App Check and debug mode disabled. A subsequent hosted cloud-only request succeeded after restricting the browser key to the approved origins. Earlier development checks used registered App Check development tokens. The returned SDK source labels were checked. These observations establish the exercised paths, not the exact Nano generation, task-traffic locality or measured semantic benefit.

Inspect task-scoped traffic; verify Chrome/Nano eligibility; complete and qualify the generated-code runner; compare coder-only, deterministic repair and Nano repair on frozen held-out tasks; measure actual cold/warm latency, memory and failures in both model load orders. Test any hosted-origin companion pairing and Chrome local-network permissions separately from same-origin loopback. Validate that the cloud wire payload matches its preview. None of these outcomes can be inferred from a source import or passing fake-provider tests.
